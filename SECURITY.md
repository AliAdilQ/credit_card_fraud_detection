# Security policy

This is an educational demonstration with a publicly accessible demo workflow, SQLite, and a synthetic-data model. It has not been assessed for financial production use.

- Do not submit real card numbers, CVVs, PINs, bank account credentials, identities, or customer records. Only synthetic transaction metadata belongs here.
- `admin / DemoAdmin123!` is a **local development account only**. The creation command refuses to run when `DEBUG=False`, and preserves existing accounts.
- Before any public deployment, change the administrator password, supply a unique secret key, turn off debug, configure allowed hosts and trusted origins, and use HTTPS. Run `python manage.py check --deploy` in that environment.
- Add user authentication, authorization, rate limiting, operational monitoring, and appropriate data retention before exposing transaction workflows beyond a sandbox. Deployments need a maintained server and database configuration.
- Joblib artifacts use pickle and can execute code when loaded. Load only artifacts generated by this repository from a trusted environment. Never replace the model with an untrusted downloaded pickle.
- Dependencies must receive security updates. The compatible version ranges are not a promise of future security.

Report vulnerabilities through the repository's GitHub **Security → Report a vulnerability** option if enabled: [Security](https://github.com/AliAdilQ/credit_card_fraud_detection/security). If private reporting is unavailable, use a GitHub issue to request a private contact channel, without disclosing exploit details, credentials, or sensitive data publicly. Include affected versions and a minimal synthetic reproduction when a private channel is established.
